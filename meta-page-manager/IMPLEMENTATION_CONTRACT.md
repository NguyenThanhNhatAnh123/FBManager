# Page Manager workspace contract

Primary entry: `http://127.0.0.1:8000/pages/`, mounted under the Chrome Manager ASGI host at port 8000. Chrome Manager remains at `/`; the switcher navigates between these two paths on one origin. The host wrapper lazily loads the Page Manager app factory from this project's `backend/` and passes `base_path='/pages'`; Page Manager has its own services, SQLite database `data/page-manager.sqlite3`, token storage and DPAPI application context. It does not import Chrome Manager APIs or attach, migrate or access Chrome profile/proxy/schedule data.

`start.bat` opens or starts the sibling Chrome Manager host and navigates to `/pages/`, normally using the host's existing Python runtime and dependencies. Optional `start-standalone.bat` uses this project's own `.venv` and serves `http://127.0.0.1:8010/` with `base_path=''`. The host wrapper and standalone launcher acquire the same `data/page-manager.lock` before creating the Page Manager app and hold it for their lifetimes; these modes cannot access the same Page Manager database simultaneously. `create_app` itself does not own this process-level lock. The optional standalone environment does not control the shared host's port.

Current scope: local token connections, explicit token check/sync, canonical deduplicated Page catalog, per-connection Page access, details/recent published posts, explicit Page information/image edits and safe activity. Scheduled publishing and inviting are separate future features. Tokens are entered in the local app, DPAPI encrypted with app-specific context, never returned/logged or kept in browser storage.

## Storage

- `connections`: numeric id, label, token_type (`user`, `system_user`, `page`), optional app_id/business_id, encrypted_token, token_revision, identity_id/name, status, permissions (nullable), expires_at (nullable), checked_at/synced_at, safe error, connected flag. App credential tokens (`APP_ID|APP_SECRET`) are unsupported for Page authorization.
- `pages`: canonical numeric Meta Page ID PRIMARY KEY; name/category/link, detail cache with timestamp and safe error. Same Page via multiple tokens appears once. Strictly increasing operation-start metadata timestamps prevent an older catalog or detail response from overwriting a newer one across connections; completion time does not decide freshness.
- `connection_pages`: UNIQUE(connection_id,page_id), source edges, active, encrypted Page token if returned, tasks/permissions if known. Rotation/disconnection immediately invalidates derived token use. Other connections stay intact.
- `posts`: UNIQUE(page_id,post_id), whitelisted message/created_time/permalink. Recent snapshot membership is separate from retained history, so removed or older cached posts do not inflate the current snapshot. Cached GET detail/posts remain readable after disconnect; network refresh requires an active linkage to the selected connection. Refreshes for the same canonical Page are serialized across connections. Partial/error sync adds safe newly seen results without removing cached links or known source edges; a complete successful sync replaces source edges and deactivates missing links for that connection. Token revisions reject stale in-flight writes.
- `events`: bounded safe event/status text, no raw Meta errors/request URLs/secrets.
- `reel_assets`: private UUID-named MP4/M4V/MOV files under this app's reel-assets, bounded streaming upload, immutable size/hash/path metadata. Public API excludes path/hash. Not shared with Chrome.
- `reel_jobs`: UUID request and payload hash bind Page/source/token revision/asset/caption/UTC instant/local time/zone/fold. Snapshot names are for display. Per-POST monotonic latches, ACKs, timestamps and immutable video ID survive restart; unknown requests never automatically replay. Completed is terminal.
- `page_edits`: durable UUID, exact connection/revision/Page/kind and SHA-256 payload binding; started/accepted/failed/partial/unknown outcome, fixed safe message and optional uploaded photo ID. No bio, address, token, image bytes or filename stored here. A started record is uncertainty on replay, including after restart. Terminal results and uploaded photo IDs are immutable. SQLite write transactions protect the replay latch across independent Store connections.

## HTTP

All calls are same-origin and loopback-only. Routes below are relative to the Page Manager app: the primary host exposes `/pages/api/...`; standalone exposes `/api/...`. The mounted boundary validates and strips authoritative ASGI `scope.root_path='/pages'` before API authentication, because the parent mount retains the original `/pages/api/...` path.

`/api/session` returns `{csrf_token,app:{name,version,graph_version,timezone,base_path,chrome_manager_url,page_manager_url}}`. Mounted mode sets `mpm_pages_session` with Path `/pages/`; standalone sets `mpm_session` with Path `/`. Both are HttpOnly/SameSite Strict and distinct from Chrome Manager's `cm_session`. Each Page Manager instance has its own CSRF secret; all API writes require `X-MPM-CSRF`. Sharing one origin does not reuse Chrome Manager's API session or database. No cross-origin API/CORS sharing is enabled. JSON errors are `{detail:string,code?:string}` without validation input echo.

- `GET /api/overview?timezone=America%2FLos_Angeles`: `{stats:{pages,connections,working_connections,needs_attention,pages_with_posts_today,today_count_known},updated_at}`. Today counts derive from available post cache; unknown/truncated coverage is explicit.
- `GET /api/connections`: `{items:Connection[]}`.
- `POST /api/connections`: `{label,token_type,token,app_id?:string,business_id?:string}` -> `Connection`.
- `PUT /api/connections/{id}`: same metadata, optional replacement `token`; secret write-only. -> `Connection`.
- `DELETE /api/connections/{id}`: disconnect/erase this connection's secret and derived Page tokens; keep canonical history/other connections. -> `{ok:true}`.
- `POST /api/connections/{id}/check`: -> `{connection:Connection}`.
- `POST /api/connections/{id}/sync`: -> `{connection:Connection,pages_seen:number,complete:boolean}`.
- `GET /api/pages?connection_id=&search=&status=&timezone=`: `{items:Page[]}`. One canonical row per Meta Page ID.
- `GET /api/pages/{page_id}?timezone=`: `{page:Page,posts:Post[],posts_has_more:boolean,posts_checked_at:string|null,posts_error:string|null}`.
- `POST /api/pages/{page_id}/refresh`: `{connection_id?:number,include_posts:true,limit:25}` -> same detail shape. Explicit selected connection must link to that Page; default deterministic active healthy source.
- `POST /api/pages/{page_id}/edit-options`: `{connection_id:number}` explicitly reads supported current edit fields. Returns `{page_id,connection_id,current:{bio,bio_field,location,category_ids,category_list},supported_fields,unavailable_fields,limits,warnings}`. A selected source must be actively bound and its derived/resolved Page token must report `/me.id == page_id`.
- `GET /api/pages/{page_id}/categories?connection_id=&q=`: source-bound Meta category taxonomy, flattened/bounded and filtered locally; `{items:[{id,name}],complete}`. No invented IDs or free-form Graph URL. Cache keys include Page, connection and token revision.
- `POST /api/pages/{page_id}/edit`: `{connection_id,request_id:UUID,bio?,location?:{street?,city?,state?,country?,zip?},category_ids?:string[]}`. Only provided editable fields are mapped to a single Graph POST. Bio is bounded to 101 characters by app policy, category IDs to 1–3 unique numeric values. A rejected native-bio read can select documented `about` before writing; never retry a write using a different field.
- `POST /api/pages/{page_id}/image?connection_id=&kind=avatar|cover&request_id=UUID`: raw local JPEG/PNG content with matching MIME, max 8 MiB and 20 million pixels. Decode/verify and complete-container checks precede any Meta call. No remote URL or filesystem path input. Larger video allowance applies only to the separate exact Reel asset route.
- Edit results: `{ok,outcome:accepted|failed|partial|unknown,message,requires_refresh}`. An acknowledged unpublished photo upload is checkpointed before photo ID assignment to avatar/cover. Partial/uncertain operations never automatically upload, retry, roll back or resume. Idempotent replay uses the saved UUID result; different content/source/Page with the same UUID rejects. Metadata and post caches remain unchanged until an explicit readback.
- `GET /api/events?limit=50&offset=0`: `{items:Event[],total,limit,offset}`. `limit` is 1–100 and `offset` nonnegative; reads retained local events only (retention remains 500).
- `GET /api/video-source?limit=100&offset=0`: source settings/stats plus `{items,total,limit,offset}` with the same bounded paging parameters. No scan, scheduling or import on GET.
- `GET /api/reels/config`: running state, active count, 1 GiB application upload limit, extensions, IANA zones/default zone and max parallel 2.
- `GET /api/reels/assets?limit=12&offset=0&search=&status=all`: SQL-filtered `{assets,total,limit,offset,summary}`; statuses are all/unused/scheduled/published. Each asset exposes at most 3 linked public jobs, a full linked count and published flag; no path/hash/checkpoint. No-limit calls preserve the legacy `{assets}` contract. `POST` uses raw octet-stream, percent-encoded `X-Filename`, own CSRF, streaming bound (no body aggregation), returns `{asset}`. Only this exact authenticated upload route has the 1 GiB allowance. JSON writes retain 128 KB, Page image writes 8 MiB.
- `GET /api/reels/assets/{uuid}/video`: owned recorded file only, size/SHA checked off-thread, local range preview. No user path or remote URL.
- `GET /api/reels`: `{jobs:Job[],scheduler:{scheduler_running,active_count}}`; no network or publishing side effects.
- `POST /api/reels`: `{request_id:UUID,page_id,connection_id,asset_id,caption,scheduled_local,timezone,fold?}` creates a future local schedule after exact active Page/source and asset validation. ZoneInfo round-trip rejects missing DST times; repeated wall times need fold choice. Same UUID/body returns saved job; changed body conflicts. Response `{job,replayed}`. Session advertises `app.token_reels=true`; old servers cannot offer creation.
- `POST /api/reels/{id}/cancel|resume|verify`: own CSRF, return `{job}`. Cancel does not delete Meta content. Resume never resets latches, rebinds token revision or repeats unknown writes. Verify reads saved video only. Completed cannot run again. Public jobs include request_id and action capabilities, never token/path/upload URL.

`Connection`: `{id,label,token_type,app_id,business_id,identity_id,identity_name,status,has_token,permissions,expires_at,checked_at,synced_at,error,connected,page_count}`. Status: unchecked, working, permission_limited, invalid, rate_limited, error, disconnected. Expiry/grants unknown remain null; do not claim permanent tokens.

`Page`: `{id,name,category,link,status,connections:[{id,label,status,sources,tasks,has_page_token}],details:{about?,website?,phone?,location?,followers_count?},checked_at,error,posts_today:number|null,posts_today_complete:boolean,posts_checked_at}`. Status: active, needs_attention, disconnected. `Post`: `{id,message,created_time,permalink_url}`. `Event`: `{id,action,status,message,connection_label,created_at}`.

## Graph transport

Pin `v26.0` by default (official Meta Business SDK config), configurable validated version. Fixed graph.facebook.com origin, Bearer header only, no redirects/environment proxy inheritance. GET paths and the three explicit Page POST targets are separately allowlisted. POST uses bounded form fields or multipart photo bytes and never retries automatically. Cursor pagination reconstructs known endpoints rather than following paging.next URLs. Bound responses/page count/posts/timeouts. User token: `/me/accounts`. System user: `/{identity_id}/assigned_pages` without business scope; with explicit business_id use Business `/owned_pages` and `/client_pages` and clearly report partial permission failures. Page token: `/me` Page fields. `/me/permissions` metadata only when supported; no fake expiry/grants. Page posts via `/{page_id}/posts` using available derived Page token or the authorized connection token. Fields are whitelisted and optional-field failures must not erase caches. Page edits require a Page token verified against the exact target; System User credentials are resolved server-side to such a token first.

## Frontend

Plain HTML/CSS/ES modules with relative assets/API paths: `/pages/static/*` in the primary host, `/static/*` in standalone mode. No CDN or Node build. Locally served Geist fonts and dark workspace theme match Chrome Manager. The app starts directly on Pages. Primary sidebar: Pages, Lịch đăng Page, Lịch đã lưu; bottom Settings. Saved schedules is immediately below schedule creation. The former Dashboard view is removed. Settings contains Overview, token connections and activity, with keyboard-accessible tabs. The token scheduling view has Page/source/video/caption/time selection and frozen public-audience review. The separate saved view has the independent token queue, local video previews, filters, bounded pagination and existing flag-gated actions; no Chrome queue import. One scheduler controller preserves draft/review state between compose and saved views. Previews require exact job asset ID and authenticated same-origin app namespace; unavailable media has a fallback, never an external URL fallback. Read-only polling preserves mounted video nodes and playback position; leaving the view pauses playback. GET polling never creates schedules or retries mutations. Page detail drawer and clear loading/empty/error/partial/stale states remain available. No token persistence in browser; clear form on save/close; DOM textContent for dynamic data. Counts deduplicate canonical Page IDs and post IDs. Session/CSRF failures reinitialize once and never replay token writes automatically. API source selection/reset must prevent stale detail responses showing under another selected Page.

Saved schedule cards display only the Page name, caption and local video. Clicking the Page name or card background opens a detail dialog with current metadata, status, published link and existing flag-gated actions. Video controls and selected text do not open details. Polling updates the selected job by ID without replacing its preview; leaving Saved closes the dialog.

The shared `pagination.js` controls Page, connection, cached post, activity, idea, video, ranking and source-item lists. Browser reads pass bounded `limit/offset` and filters to SQL; totals/canonical identity and sorting precede LIMIT. The server hydrates only visible rows and their scoped bindings/variants/runs. Overview uses aggregates. `GET /api/pages` accepts bounded paging plus connection/search/status/today/timezone; `GET /api/connections` supports bounded paging/search and `/api/connections/options` returns thin paged selector records. `GET /api/pages/{id}` uses `limit/offset` for cached posts with `posts_total/posts_limit/posts_offset`. Query/filter/page-size changes reset the page; shrinking result counts clamp/refetch. Library state is separate per tab; unchanged polls preserve media nodes/frames. Old no-limit APIs remain compatible for workers/MCP; new browser paths never call full-list APIs as polling fallbacks on the updated server.

`GET /api/idea-pipeline?summary=true&limit=12&offset=0&search=&status=all&sort=warehouse` returns aggregate readiness plus a SQL window of ideas and only their variants/current metrics/latest runs. Sorting by views runs in SQL, with unknown values distinct from zero. Summary-only reads have no idea rows/runs/performance hydration. Optional `ranking_limit/ranking_offset` requests SQL-ranked cohorts only when expanded; the read path avoids recursive legacy status/ranking/list calls. `GET /api/reels?limit=12&offset=0&search=&status=all` returns `{jobs,total,limit,offset,scheduler}`, with each job's exact public asset embedded; saved-list polling never loads the whole asset library. `request_id` supports exact uncertainty recovery and `GET /api/reels/{id}` reads one current job. Compose choices use searchable 25-item SQL windows and retain their selected Page/asset separately. Leaving the view releases video sources/decoders, while drafts and review UUIDs remain in memory.

The content library uses compact cards; per-item diagnostics, IDs and linked-job history are disclosed on demand and their DOM is released when closed. Import instructions and folder scanning are behind a closed disclosure; existing upload/run/cancel guards and request IDs remain unchanged. Video-source configuration is closed by default and defers Page/connection choice reads until opened. Closing it preserves the local draft, keeps dirty state visible and prevents scanning unsaved criteria. Queue disclosures expose messages/IDs without saving, scanning or enqueueing. Opening tabs, disclosures, pagination and read refreshes do not create content or schedules.

Uploader readiness selects a ready local PODSach service at `http://127.0.0.1:8770` before the fixed web base `https://ul.eagleglobal2023.com/s/blueox179.com`. The optional web session is stored as one DPAPI-encrypted cookie blob in `uploader_remote_session`; no password or browser/shop auth file is retained or copied. Login uses the fixed origin's root login endpoint, then exact protected GET `/s/blueox179.com/api/overview` must succeed before persistence. Normal web clients restrict API/media requests to the Blueox namespace and validate the returned domain; the hosted gateway strips `X-PODSach-Expected-Shop`, so that header alone is not a web isolation guarantee. Local clients retain the expected-shop header guard. Only internal gateway-issued GET ticket polling may additionally access `/s/blueox179.com/_gw/ticket/<id>`; the original POST is never replayed. Initial explicit web probes allow the gateway's 60-second response window; passive readiness remains short. Status polling never calls `/api/session/check`; only CSRF-protected explicit session-check does. Modern overview cookie hints are not login proof: the explicit shop-check result is persisted for 300 seconds and fenced to the exact web-session revision captured before the probe. Connect/disconnect invalidate that proof. These endpoints inherit the Page Manager origin/session/CSRF boundary under `/api/idea-pipeline/upload/`.

After the credential POST, login probes the protected overview before following UI navigation. A verified API session is persisted without visiting a dashboard redirect. Pending authentication may use at most three known safe landing GETs, probing the protected API after each hop; the credential POST is never replayed. Cookie scope may be the exact UL host or the EagleGlobal parent when issued by UL, but persisted cookies are narrowed to the UL host and sibling-origin requests remain forbidden. Safe in-process login diagnostics contain only stage/reason enums and HTTP status, never response bodies, cookies or credentials.

New run payloads bind `{kind,endpoint,shop}` at acceptance, hash that binding with the other immutable inputs, and stage it in `run-input.json`. `scripts/uploader_client.py` verifies the canonical active DB run, fence, cancellation state, artwork hash and seven variant bindings before requests. It has no endpoint fallback; mutating calls are journaled before I/O and ambiguous operations cannot be replayed. Only owned input/review/export batches may be processed. Template policy maps black lettering to `campaign_source`/zitat25 and white lettering to `black_campaign_source`/ge2610; mixed or unknown lettering requires review. This connection work does not itself authorize product or Reel creation.

## Token Reel runtime

An independent ReelGraphClient implements start on the selected Page's video_reels edge, fixed HTTPS rupload binary stream and finish/PUBLISHED with description. Validate/discard the returned upload URL; only the exact configured version/video-ID route on rupload.facebook.com is accepted. OAuth header only on that fixed origin, no redirects; all other Graph requests use Bearer headers. Open-file SHA/stat and rolling stream hash prevent changed assets reaching finish. Validate /me.id against the exact Page before any POST and recheck the connection revision before each write.

Each external POST is latched before sending. Unknown results and interrupted unacknowledged writes can only be reconciled with GET on the saved video, never repeated. Upload completion (not processing completion) permits the first finish; final success requires the exact video ID, matching Page owner, publishing_phase complete and canonical published link. Explicit phase errors pause. Conservatively limit this queue to 30 finish attempts per Page/rolling24h; Meta remains authoritative for activity outside the app.

The host watch loop calls PageWorkspace.tick; cancel the host monitor, await the Page Manager scheduler shutdown, then release its private file lock. Mounted child lifespan is not assumed to run. Standalone lifespan owns its timer. At most two token jobs run, serialized by Page and source including concurrent Page editing/refresh. Active jobs recover to needs_review after restart if any POST was attempted, otherwise scheduled. Scheduled due work resumes when the server returns. This is a local server schedule, not a Meta-hosted schedule while the PC is off.

The separate edit dialog freezes Page/source and staged file previews on review; only explicit Save invokes mutations. Source/Page changes discard previews and ignore stale read/search responses. The server session advertises `app.page_editing` so older servers cannot present a functioning Save flow before restart. Result screens show per-operation acknowledgment or uncertainty and explicit readback, without optimistic cache updates or a retry button after an attempt. The CSP permits local blob previews, not arbitrary image hosts.
